# 全索引文献版本匹配（v0.6 候选版）

[English](VERSION-MATCHING.md) · [版本详情](VERSIONS.zh-CN.md)

这项可选流程关联 OpenAlex 中彼此独立的文献记录，复用已发布检索索引，
并保留父版本的全部已确认关联，包括地学范围以外的 arXiv 关联。
原始文献 JSON、参考文献、OA、引用计数、检索分页和导出 ID 均保留原记录语义。
后台匹配可以与现有服务并行运行；软件升级与关联数据发布分别验收。

## 输入和处理步骤

前置条件是已验证的元数据代、已发布文本索引、已验证分类集合，以及已发布的
父关联版本。当前实现要求存在父版本，可先通过既有 arXiv 关联流程生成。

1. **特征目录：**顺序读取 Manticore 中的标题、完整作者身份、年份、类型和标识符，
   写入独立 ClickHouse 目录。不重建文本索引，不逐篇调用在线 API。
   每批写入回读验证后保存检查点和内容摘要，中断后可以幂等重放。
2. **试点：**仅对文献 ID 排序，查询限制为 8 GiB、两个线程；固定选中 ID 的回执后，
   分批读取特征并回读核验、保存检查点，避免全库完整内容参与排序导致内存超限。
   从整个已发布文献索引按确定性哈希均匀选取约百万篇，独立于旧版十万篇试点。
   后续批次排除已处理记录。
3. **候选生成：**使用规范化标题、作者与标题内容词组合，并为没有候选的预印本提供
   有界的原生标题词检索。组合采用最长的四个有效词近似稀有词，尚未实现全库词频筛选。
   DOI 候选可查询已导入的全量元数据，但共享 DOI 本身仍需审核。
   既有精确 arXiv 关联从父版本继承；标题检索仅覆盖已发布索引。
4. **自动评估：**默认采用自动规则，不需要人工标签或样本配额。可选
   `--review-mode independent` 按连通分量准备开发集 500 对、盲审 600 对、负例 400 对。
5. **关联与验收：**在父版本完整快照上增补通过自动评估或独立校准且直接验证的发表版关联。
   每个新成员必须直接匹配发表版锚点；竞争发表版和跨既有版本组连接保留待审。
   发布前验证覆盖数量和版本组成员的双向一致性。

特征、候选算法和确认规则分别记录身份。特征目录包含候选倒排投影，因此修改该投影
需要新目录；仅修改确认策略可复用兼容特征。只为拟确认关联和索引外 DOI 候选读取
完整原始记录，避免全量随机读取 JSON。引用中的特征库、检查点、父版本和索引依赖
都需要长期保留。

## 自动关联边界

默认 `--review-mode automatic` 使用确定性规则，不调用模型，也不生成虚假的人工标签。
除了原有无冲突及 0.99／0.85／0.03 条件，还要求规范化标题完全一致、至少四个词且
不少于 20 个字符，具有强作者身份、唯一发表版锚点，版本年份差不超过三年。
已知关联从父版本保留。拟确认记录需核对冻结原始摘要及撤稿／通知标志；竞争锚点和
跨既有版本组冲突仍保留为候选。未确定候选不阻塞批次等待人工处理。

自动判定记录 `automatic_bibliographic`、规则身份及 `independent_review: false`。
API 状态和版本组下载明确提供评估方式，网页提示关联由自动规则判定。
这不代表独立人工校准通过，也没有实测精度保证。下文 600 对和每层 100 对的要求
仅适用于可选的独立人工审核模式。

候选年份窗口为 ±10 年；缺失年份保持待审。每篇最多保留 200 个候选，达到截断条件
标为 `overflow_review`，不能计为未匹配。作者姓名只作弱证据；要求共同 ORCID，或
至少两个稳定作者 ID；两边都为单作者且共享同一作者 ID 时例外。
自动关联仅允许预印本与发表版。更正、撤稿、数字或否定词冲突、DOI 歧义、重复发表和
扩展论文等仍需审核。

标题相似度是可解释的字符串分数，**不是正确概率**。当前提供
0.99／0.98／0.97／0.96 的诊断网格；首轮盲审将自动接受阈值固定为 **0.99**，
标题词重合率至少 **0.85**，候选分数间隔至少 **0.03**，竞争锚点按网格最宽松阈值检查。
降低阈值需要新规则和新的独立盲审，不能利用已经看过的盲审标签调参。

选择 `--review-mode independent` 时，人工审核需标注 `same_study`、`different_study` 或 `uncertain`，填写审核人，
并声明 `independent_review: true`。不得生成标签冒充审核。
600 对盲审必须全部为可自动确认的真实关联，困难负例不能发生自动误合并。
600 对零错误对应单侧 95% 精度下界约 99.5%，不代表全库召回率。
只有至少获得 100 个盲审样例的分层可自动确认。
失败或已使用的盲审不能通过改标签重试；兼容后续批次可继承已通过校准及其来源证明。

## 运行方法

使用已安装的 `oa` 并指定正确工作目录。示例名称可自行替换；本地路径和实际数据规模
不写入社区 Git。

```bash
oa versions plan --profile full-index --release earth_match_pilot \
  --pilot-size 1000000 --workers 4
oa versions run --release earth_match_pilot --until validate
oa versions status --release earth_match_pilot
oa versions stop --release earth_match_pilot
oa versions resume --release earth_match_pilot --until validate
```

自动模式默认继续完成评估、分组和验收；发布仍需单独执行。
`automatic-review.json` 记录规则及已评估／符合条件／未确定数量，不声明独立校准通过。
`--until review` 仅准备自动规则，逐条评估在分组阶段执行。改变评估方式时创建新 release，
在兼容性证明后复用特征和候选，不修改旧 release 或生成虚假的人工标签。

```bash
oa versions publish --release earth_match_pilot
```

可选独立人工模式会在 `var/versions/<release>/` 下生成 `review-development.json`、`review-blind.json`，
以及含固定分组和分数的内部 `review-package.json`。审核人使用前两个文件，
盲审人不应查看内部角色映射和分数。汇总标签文件包含 `identity`、
`independent_review: true` 和 `pairs`（每条含 `id`、`label`、`reviewer`）。

```bash
oa versions plan --profile full-index --release earth_match_independent \
  --review-mode independent
oa versions run --release earth_match_independent --until review
oa versions review-import --release earth_match_independent --labels /local/reviews.json
oa versions run --release earth_match_independent --until validate
oa versions publish --release earth_match_independent
oa versions plan --profile full-index --release earth_match_core \
  --stratum 01_core_journals --batch-size 5000000
```

后续按核心期刊、作者支持、泛地学顺序分批执行，每批约五百万篇，分层名以固定索引为准。
每个新版本分别走完相同步骤。默认 `run` 停在审核阶段，没有自动绕过审核的发布。
未提供标签时仍可生成并发布“父版本确认关联＋新待审候选”的兼容快照，
但不会因此确认新增文献匹配。

## API、网页与运维

- `/v1/works/{id}/version-group`：确认组和原始命中记录；新格式额外区分已处理和未处理。
- `/v1/works/{id}/version-candidates`：候选证据、审核状态和处理状态；支持
  `relationship_release`、`per_page`，游标固定关联版本和查询文献。
- `/v1/version-groups/{id}`：当前关联版本中的原始成员元数据。
- `/v1/works/{id}/versions`：继续保留 arXiv 来源关联语义。

网页区分已确认成员和待审候选，支持查看证据，不跨版本转移参考文献。
特征覆盖、匹配覆盖、审核和发布是不同状态；扫描完成不代表每篇都有另一版本。

进度记录已提交数量、候选数、溢出数、处理字节、工作线程、速度和 ETA。
先保守启动，观察检索延迟后再增加并发。同 Pod 检查不能证明跨 Pod 可达性或高并发容量。
本流程无需重启元数据或检索引擎，更不能绕过校验和检查。升级时保留兼容的旧运行环境
及关联指针用于回滚。

候选查询同时按数量和转义后的 UTF-8 SQL 字节数拆批，每批值列表限制为 128 KiB，低于默认 256 KiB 解析上限。此限制覆盖标题／作者候选键、目标特征、DOI 和父版本成员查询。单个检索键超长时，文献保留为溢出待审。

后台候选任务的 workers 也控制独立 ClickHouse 读取的并发数；返回顺序保持确定，原有字节限制不变。先检查年份窗口，并利用字符串相似度的严格上界，跳过原规则必然丢弃的配对。候选规则、保留证据和独立审核门槛均不改变。增加后台 workers 前先测前台 API 延迟。

## 大规模审核与恢复

候选消费改用有界的主键分页，每页 HTTP 响应完整读取并关闭后再处理。审核以每页
10,000 条读取紧凑证据和 ID，写入 `review-staging.sqlite`，使用 FULL 同步与 DELETE
日志。每个事务同时提交记录和输入游标；失败页从最后提交游标恢复，不重跑特征提取
或候选匹配。

暂存库保留每对文献首次出现方向的去重语义、确定性排序和全部图连接，不将数百万份
完整候选留在 Python 内存。连通分量使用迭代路径压缩，每个分量只计算一次审核分组；
仅为最终选中的审核对读取完整元数据。审核数量、盲审隔离和独立标签要求保持不变；
独立分量不足时仍不能通过验收。连通图阶段中断后，可从紧凑暂存数据重新构建。

`review-progress.json` 区分读取、连通分量构建和抽样阶段，单位为候选／图记录，
不同于已处理的源文献数。审核包提交后，可以重建中断的公开审核导出，无需重新抽样。
输入身份变化，或现有审核包与已提交暂存记录不一致时，必须报错。

审核实现纳入关联签名；升级需创建新关联 release 并保留兼容运行时。复用已完成的
样本、覆盖和候选表前，须比较语义身份、实际数量和内容凭据，不能修改旧签名。
单独验收发布前，正式关联指针不变。

原生标题回退查询在同一批次的有界线程池中共享一个 HTTP 客户端，等全部线程结束后
关闭；查询失败时也会关闭。每篇文献不再重复初始化连接池和 TLS 上下文，没有回退
查询的批次不创建客户端。查询语句、结果上限、证据和审核门槛不变。此实现变化需要
新关联 release／运行环境；兼容的冻结特征及已提交候选进度可在数量、内容证明一致
后复用，无需重算。

版本特征规则 v2 在识别通知及撤稿前，先规范 Manticore 返回的 JSON 标量撤稿标志
（`"0"`／`"1"`）。接受布尔值、整数 0／1 及相应 JSON 字面量字符串；未知值立即
停止提取。普通文献的 false 不会触发拦截，真实撤稿及通知标题、类型仍会被拦截。
旧规则可能将非空字符串 `"0"` 错判为 true，造成没有合格盲审候选。旧特征内容、
候选判定及审核包不能原样复用，须创建新关联 release 并重新生成这些派生产物。
冻结的元数据和文本索引仍可复用，无需重建全文索引。保留旧 release／运行环境，
不能修改旧签名来接受新实现。

## CPU 加速与断点迁移（rc9）

`--workers` 控制数据库读取并发；新增 `--score-workers` 单独配置 1–16 个持久 CPU
评分进程，默认 1。评分保持原字符串分数、源文献级候选分差及顺序，子进程不开数据库
连接、不写检查点。主进程每 2,000 篇写入并验证；并行模式最多提前准备一个批次。
工作进程失败时不推进当前批次断点；进程树 RSS 超过 64 GiB 时受控停止，无需 GPU／NPU。

版本组批量读取父关系，每次最多提交 2,000 组或 16 MiB，回读通过后才推进锚点检查点。
父版本导入另有凭据，恢复时不会用旧父快照覆盖已完成的扩展组；跨分块的竞争锚点仍会阻止关联。

```bash
oa versions plan --profile full-index --release earth_match_fast \
  --stratum 03_author_supported --batch-size 5000000 \
  --workers 8 --score-workers 8
# 先停止旧任务，并保留其原软件和输入文件。
oa versions stop --release earth_match_previous
# 确认源任务退出、状态为 paused 后：
oa versions migrate --release earth_match_fast --from-release earth_match_previous
oa versions resume --release earth_match_fast --until validate
```

迁移目标必须具有相同父版本、选取范围、特征及判断规则。迁移逐表核对冻结选取 ID、特征、
候选和覆盖数据的有序 SHA256 内容摘要及数量，排除尚未提交的源批次尾部。复用已确认的候选
断点，按需重做评估和分组。新实现必须使用新 release，不改写旧清单和签名。仅明确验收的
历史生产程序可兼容读取，未知签名仍拒绝；只读兼容不允许用新程序运行或发布旧 release。

CLI 状态和 HTTP 版本状态增加 `progress_summary`。严格口径分别为：完整检查范围内已关联的
唯一源文献数、完成全流程检查的源文献数、全部冻结候选源文献数。候选生成遍历量、有方向的
候选对数量和溢出量分别统计。关联数量在验收／发布时计算并缓存，HTTP 请求不执行全库统计。
可选进度凭据缺失会明确报告进度错误，不影响有效的正式关联。运行批次的新关联需等评估、
验收及发布完成后才计入正式结果。
