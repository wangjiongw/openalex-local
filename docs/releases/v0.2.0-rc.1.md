# OpenAlex Local v0.2.0-rc.1

This candidate freezes a native toolchain for a user-downloaded OpenAlex JSONL
snapshot: local verification, resumable metadata/citation processing, optional
Earth-science collections and Manticore indexing, and CLI/API/web deployment.

Git tag: `v0.2.0-rc.1`; package and application version: `0.2.0rc1`.

## Included

- Legacy/current JSONL manifest readers with preserved source records and fields.
- Default metadata-only import, identifier mapping, citation audit and publication.
- Optional Earth profile with collection export, indexed text/filter queries,
  immutable search snapshots and explicit validation/publication.
- Workspace/code separation, pinned native engines, offline caches and supported
  Linux x86_64/ARM64 native workflows; documented older-ARM compatibility profile.
- DOI/ID and batch lookup, reference/citation/related-work expansion, indexed
  title/abstract/author-name queries, supported filters and a local web UI.
- Guarded read-only existing-data adoption and search recovery tools.
- Fix Manticore snapshot import under parent directories containing dots.

## Upgrade and installation

Install the tagged source or attached wheel in a virtual environment; verify the
wheel/source archive against `SHA256SUMS.txt`. Data, private configuration and
engine binaries are not bundled. Follow [the deployment guide](../QUICKSTART.md)
and [release operations](../RELEASE.md).

Snapshots are acquired by the user; there is no project snapshot downloader.
The default profile is `metadata`; existing Earth plans must explicitly pass
`--profile earth_sciences`. Use `engines ensure --search` for the optional engine.
No query semantics or index layout changes accompany this version freeze.

## Validation and boundaries

See [validation evidence](../VALIDATION.md) for completed checks and their scope.
Internal published indexes and prior full search-recovery evidence are retained;
the candidate does not rebuild production indexes or replace the internal service.

This is a prerelease, not complete official API parity. Full-discipline text,
PDF/TEI downloading, Parquet import, live sync/deletions/merged IDs, automatic
version grouping, semantic search and SDK/MCP are follow-up work. Search restore
is not independent ClickHouse disaster recovery. Source data may be missing
abstracts or references; historical internal storage errors are not declared fixed.
