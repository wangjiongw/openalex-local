# v0.6.0rc4 — parallel candidate reads

[中文](v0.6.0rc4.zh-CN.md)

Independent byte-bounded postings, feature and parent-member reads now use the
existing offline worker setting concurrently. Cheap year rejection and strict
upper bounds on string similarity skip only pairs discarded by the original
policy. The foreground API, index projections, candidate rules and independent
review gates are unchanged. Check foreground latency when increasing workers.

Validation: 473 unit tests passed (77 opt-in skipped); isolated Earth native flow
passed; all 90 package files match source and installed bytes. One frozen real
2,000-work batch took 112.9 seconds with the serial reader and 53.5 seconds with
eight readers (2.11×), while all 1,560 candidate payloads matched byte for byte.
This is a single-batch result under concurrent background load, not a full-corpus
throughput or cross-Pod capacity claim. A larger lookup batch gave only a marginal
single-batch benefit and was not selected.

Retain old runtimes and releases. Carry only checkpointed, compatible features,
sample and candidate results into a new immutable release, reconcile copied
artifacts and continue from the saved cursor. Upgrade compatible serving software
before publishing the new relationship data.
