# v0.4.0 — optional arXiv source and confirmed versions

[中文](v0.4.0.zh-CN.md) · [Operations](../RELEASE.md)

This release adds a separately optional arXiv workflow to the existing OpenAlex snapshot service. Users download the Kaggle JSONL metadata file, configure its local path, then run the resumable normalize → link → store → index → validate → publish stages. Snapshot acquisition and all source/index data remain outside Git.

The default selector includes first submissions from 2010 onward across all arXiv subjects. Original JSON and unknown fields, dates, authors, abstracts, categories, licenses and explicit publication DOI values are retained with provenance. A read-only derived DuckDB adapter is optional and reports unavailable original fields honestly.

All selected records, including unmatched preprints, receive independent lexical search, pagination and exports. The API and web UI switch sources explicitly; counts and ranking are not mixed. Unique exact DOI evidence can associate independent OpenAlex preprint/publication records and prefer the confirmed publication in details. Ambiguous and unmatched records remain distinct.

arXiv metadata does not supply a reference list. A confirmed publication's references retain that publication's source identity; they are never copied into arXiv raw data. Online synchronization, Crossref enrichment, PDF download and mixed-source ranking remain later work.

Install the wheel or tagged checkout, retain the previous environment, and restart the API and export worker with the new installation. Reuse compatible OpenAlex metadata and indexes. Build and explicitly publish the optional arXiv source separately; a package upgrade does not publish data. Verify `/status`, `/capabilities`, source queries and exports. Roll back software by stopping the API/worker and restarting both from the previous environment; retain the new source pointer and artifacts for recovery or explicitly restore its saved previous pointer. Do not delete either source release or export dependencies.

Software unit/native/browser checks and the operator's full-source reconciliation, persisted index checks, independent restore and query/export acceptance are separate evidence. Each installation must validate its own inputs and deployment; no dataset or machine-specific acceptance is bundled with this release.
