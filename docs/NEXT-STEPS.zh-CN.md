# 下一阶段开发计划

[English](NEXT-STEPS.md) · [项目状态](STATUS.zh-CN.md) · [路线图](ROADMAP.zh-CN.md)

本计划于 2026-11-11 按 v0.3.2 核对。下列内容均为待开发任务，不是该稳定版本已经具备的功能。
新增模块应在独立环境构建和验收，当前服务与已验收索引继续可用。


实施状态：v0.4.0 已实现独立的 M0/M1 来源工作流，见 [ARXIV.zh-CN.md](ARXIV.zh-CN.md)。社区标准输入为 Kaggle JSONL，可选兼容只读 DuckDB。小型实体目录扩展、在线同步和内容任务仍属于后续工作。下文的原里程碑描述保留规划背景，不表示所有阶段都已部署。

## 本轮确定的来源与边界

- v0.3.2 及已验收的 ClickHouse＋Manticore 索引继续作为运行基线。
- 下一来源为现有本地 arXiv 元数据，范围保持 2010 年及以后首次提交的全部学科；
  用于补元数据和版本证据，不视作结构化参考文献来源。
- 关联已确认的预印本／发表版，保留独立原始记录及书目来源；归组展示时可优先发表版。
- 当前开发范围不引入 Semantic Scholar：不接 API、不导入其数据集、不添加其 SDK；
  未来如有需要另立任务重新评估。
- Crossref API 和用户下载的公开数据文件列为后续可选来源，不作为 arXiv 接入、地学实体或现有服务的前置条件。
- 在线获取只在可选后台任务进行，普通本地查询不依赖外部服务；快照下载仍由使用者完成。

## 1. 元数据补充与身份关联

arXiv 元数据库可补摘要、作者、提交／版本日期、学科类别、许可、发表 DOI／期刊信息及来源链接，
通常不能提供结构化参考文献列表。规范化本地表还可能缺少原始 JSON、结构化作者或中间版本历史，
应核对实际 schema，不能当作未加工的完整快照。

保持现有 OpenAlex 源 JSON 不变。新增来源记录保存 source、source ID、获取／更新时间、payload
哈希与适配器版本，能取得原始响应时一并保存。增补视图标出字段来源和冲突；可补展示用摘要，
但不能声称补入内容原本就在 OpenAlex 源记录中。

优先匹配明确 arXiv 链接／ID，以及规范化后唯一的 DOI。arXiv 元数据中的 DOI 可能指正式发表论文，
`10.48550/arXiv.…` 则指预印本，两者可用于关联，但不能视为同一来源记录。
标题／作者／年份匹配在校准和核对前只给候选。不仅凭标题合并，不给未匹配 arXiv 伪造 W ID，
也不把普通作者字符串直接当作已有 OpenAlex 作者身份。

版本组保留独立记录、日期、DOI、许可和参考列表。可在可选归组视图中优先展示已确认发表版，
同时保留预印本。发表版书目可以带来源展示，但不写成预印本自己的原始参考文献。
现有 `/works` 与 `/v1/works` 契约保持兼容；没有 OpenAlex ID 的记录使用另行说明的增补／统一来源 API。

首批按此前选定范围纳入 2010 年及以后首次提交的 arXiv 全部学科，这是来源／时间范围，不等于地学分类。
arXiv 类别与 OpenAlex domain／field／topic 需明确映射；arXiv 表里的 domain 字符串不是 OpenAlex 的四个 domain。
应先测与 OpenAlex 的重叠，再估计实际新增文献数量。

## 2. 数据追更：发现新论文与完整同步分开

| 输入 | 建议用途 | 关键限制 |
| --- | --- | --- |
| arXiv 本地数据库 | 基线导入 | 构建时间不等于数据覆盖时间，要核对首次提交与更新字段 |
| arXiv OAI-PMH | 元数据增量主通道 | datestamp 表示记录修改，不是首次提交；遵循服务端 token／重试规范 |
| arXiv API | 定向读取与修补 | 遵守上游请求节奏，不作为全库采集首选 |
| arXiv RSS／Atom | 新论文发现与订阅 | 不是完整历史，也不能单独修补长时间中断 |
| OpenAlex 新公开快照 | 免费周期对账；由用户下载到独立输入路径 | 核对当前格式、删除／合并 ID 和发布说明 |
| OpenAlex 同步 API 过滤 | 有权限时对限定范围频繁追更 | 当前官方文档要求适用订阅；普通免费查询权限不等于同步权限 |
| OpenAlex 发表日期查询 | 可选的近期论文发现 | 会漏掉旧记录修正、迟到收录、删除和合并 |

2026-11-11 核对的官方说明为：OpenAlex 免费快照按季度发布，日快照／同步 API 过滤属于付费能力。
目前没有快照发布公告 feed，应监测发布说明或 manifest 日期，不沿用已被替代的每日 changefile 端点。
API／RSS 新鲜度按来源分别声明，不能宣称补入近期记录后整个旧快照已经同步到最新。

保存原始获取回执、可重放批次、来源时间、有限重试、各上游请求节奏和已提交水位。
使用重叠窗口补漏，仅在预期更新全部提交后前移水位。arXiv 应遵循 OAI 返回的 datestamp／续传 token。
日常调度前先回补已核对基线覆盖日期至首次运行之间的缺口。

不向冻结 generation 直接写实时更新并重写原凭证。设计发布清单，绑定不可变基线、来源／增补 delta、
删除／重定向和变更索引段，查询及导出固定同一有效版本。更新论文时替换其正向参考集合并调整反向边；
索引 delta 须屏蔽旧文档版本，保持精确计数和 cursor。简单并查新旧索引会重复文献和暴露旧内容。
先用小型更新／重放／恢复样例验收，限制增量层规模，再按实际成本决定何时合并整理。

批量跨版本更新应比较新旧 manifest 和 schema、应用当前删除／合并清单并对账 ID。
部分上游全库字段变更不推进逐条 `updated_date`，因此仍须读发布说明并周期对账完整版本。
上游 ID 合并与预印本／发表版的学术版本关联是两件事。普通本地查询不应依赖在线请求，外部补全单独后台执行。

## Crossref：后续可选的书目与元数据增补

Crossref 最适合在 arXiv 已确认关联发表 DOI 后使用，可补出版商提交的元数据、可用参考列表、
关系、资助与链接；覆盖取决于出版商和具体记录。它不是 arXiv 书目接口，不能假设 arXiv／DataCite
DOI 可直接在 Crossref 解析；不在 Crossref 的记录应明确标为未找到。

| 方案 | 计划用途 | 边界 |
| --- | --- | --- |
| 公开 REST API | 先用分层的 100–500 篇样本试验，再按缺失字段／目标 DOI 定向批处理 | 遵守上游限流／并发／Retry-After，按 DOI 缓存，失败与空元数据分开记录 |
| 年度公开数据文件 | 规模扩大后读取用户已下载文件，筛选目标发表 DOI | 校验格式／版本／哈希；一批 DOI 共用一次扫描，不逐篇全量扫描；预算原文件／缓存／索引磁盘 |
| Metadata Plus 月度快照 | 仅在单独决定使用订阅时考虑 | 与年度公开文件不同，本计划不假设已有权限 |

优先小规模 API 评估，再决定是否获取全量 Crossref 数据。统计目标发表 DOI 命中率、实际存在
`reference` 列表的比例、参考目标在本地解析的比例。当待补规模和 API 成本足以支持批量路线时再引入
本地公开文件。本计划本身不授权或启动任何数据获取、付费订阅。

可选模块复用 arXiv 的来源记录／字段来源契约：固定输入版本或缓存批次、保留原始响应、稳健规范化 DOI、
支持批次恢复，在 API／网页／导出说明来源和缺失。不得静默覆盖 OpenAlex 字段。
源参考条目可能只有 DOI、部分书目信息或未结构化文本，均须保留原条目和匹配状态。
`reference`、`references-count` 与 `is-referenced-by-count` 含义不同；数量为零／缺失不能证明原文无书目。

展示时区分所选源记录、关联发表版和后续全文抽取的书目，标明已确认、歧义、未解析目标。
确认目标可去重，但原始条目不能丢。发表版的 Crossref 书目不能静默成为预印本自己的原始参考文献。
既有图谱／定位契约保持兼容，增补边先显式提供，再考虑单独发布新图谱数据版本。

C1 验收：DOI 身份与来源正确、分页／批次完整、部分书目保留、重放不重复、网络失败与参考列表缺失分开、
API／网页／导出一致。不为实现本模块而加入下载器、PDF 解析、新作品索引布局或全量重入库；
全文书目恢复仍是更后的独立步骤。

## 3. 地学全部实体与更广搜索范围

全部已导入实体记录已经保存。补齐地学实体访问，是完善名称发现、文献关联、适用过滤与导出，
不等于给所有 JSON 字段都建索引，也不等于每种实体都必须成为论文过滤条件。

1. domain／field／subfield、国家／语言／许可／类型／SDG 等小词表先补查询控件；
   关键词／概念按需增加名称目录。固定词表可复用元数据查询，不必逐个引入搜索引擎索引。
2. 再补出版商／资助方名称与可信作品／来源关联。先从地学作品提取 award 关联 ID，
   统计规模后再决定是否需要全局项目索引。
3. 复用现有作者／机构／期刊／Topic；保留未解析关联和不同路由的 authorship 语义，
   新过滤必须同时验 API、网页和导出。

当前 catalog 构建器明确要求已验收地学父构建，主要实现作者／机构扩展，并非已交付的通用全实体构建器。
拓展已验证的批次、检查点和封存模式即可，无需新增插件框架。

可配置 profile 应选择 domain、field、topic、期刊或 ID 清单，明确规则版本及规模。
OpenAlex 有四个 domain，但整个 Physical Sciences 的规模可能远大于 AI／CS 子集；先做有用交叉范围，
再考虑全学科。当前 catalog 的互斥存储 owner 不等于完整多标签学科归属，选范围应使用真实来源层级标签，
重叠作品按 ID 去重，复用已封存块，仅增加未索引的作品文档。

大构建前用分层的 10 万至 100 万条样本，测每条索引字节数、构建／封存／恢复速度，以及后台写入时的 API 延迟。
据此估算耗时和磁盘，包含快照、父段和余量；不能把旧地学速度直接外推到摘要长度和结构不同的新学科。

## 4. 链接、下载与参考书目恢复

先规范化并排序源记录已有落地页／PDF 链接，区分发表版／预印本／仓储版及已知／未知许可。
随后实现显式选择的下载任务，使用可用 arXiv／仓储链接或可选的 OpenAlex 内容 API。
当前 OpenAlex 文档说明 PDF／TEI 下载按用量计费；本地免密不取消上游 key、用量或网络要求。
先确认内容可用，不假设每条元数据都有文件。

复用现有导出任务的回执、检查点、哈希和下载概念，文献文件与元数据导出分别保存。
验证实际格式、非空／可解析、最终 URL 与文献版本关联，保留 HTTP 失败原因。
下载器跟随来源 URL 时要检查跳转和私网目标，不能把上游凭据转发给无关主机；这些检查随下载功能一起实现。

补缺失书目时，优先使用明确发表版参考列表或可取得的 TEI 书目，再考虑 PDF 解析。
抽取结果要有匹配置信度、来源和可核对的未解析条目，不把不确定候选静默变成确认的 OpenAlex 引用。
缓存或下载内容不要求重建现有标题索引。

## 首个实施包与暂缓范围

下一次代码开发范围锁定为 M0＋M1，以及 M2 可独立开展的小词表部分：

1. 冻结／校验配置的本地 arXiv 输入及 2010+ 范围，对账数量、日期、重复、缺失原始／版本字段和源哈希。
2. 先实现来源记录与稳定 ID，再做精确 arXiv／DOI 关联；保留歧义和未匹配记录，建立人工复核样本。
3. API／网页／导出呈现带来源的元数据及已确认版本关联，支持可选发表优先归组，不改变 `/works` 原始响应。
4. 复用已导入实体补小型地学相关词表与名称选择。
5. 验证断点／重放、身份冲突、摘要／书目缺失、原有定位／搜索／导出兼容，以及新构建回退。

本包不启动完整新 domain 索引、Crossref 全库导入、付费同步订阅、Semantic Scholar 接入或 PDF 下载／解析部署。
范围构建耗时和磁盘经试跑再估算，arXiv 回补水位不能直接采用本地文件构建日期。

## 模块与验证要求

在现有链路上新增具体模块：可选 arXiv 来源适配、身份／版本关联、来源标记／增补投影、同步回执与发布清单、
通用范围／实体选择，最后是内容任务。每个模块须可独立由 CLI 调用，在 API／网页中呈现状态，
明确冻结输入／输出、检查点、取消／重放与验收证据。继续使用 ClickHouse＋Manticore。

配套补充来源覆盖／新鲜度／缺失率监测、身份关联标注样本、更新／删除／合并重放样例及代表性查询／导出基准。
独立数据备份／恢复也应并行安排。改变作品索引字段时，在新 build 中重建受影响投影；
仅名称目录、来源链接和内容任务无需重建全部地学作品。
