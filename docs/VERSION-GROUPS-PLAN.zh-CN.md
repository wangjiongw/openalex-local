# OpenAlex 内部版本整合计划

[English](VERSION-GROUPS-PLAN.md) · [开发路线](NEXT-STEPS.zh-CN.md)

状态：第一阶段的版本详情关联已在 v0.5.0 交付；数据验收、发布和部署分别执行。参见[操作流程](VERSIONS.zh-CN.md)。复用 arXiv 精确 DOI 证据及已验收的 ClickHouse＋Manticore 索引。分组搜索仍是后续设计，当前不提供。

## 目标与当前覆盖

地学检索是否就绪，以 `/status.search_coverage.earth_complete` 和具体 build 的范围为准。固定集合全部上线，不等于所有地学论文都已收录，也不表示所有交叉学科都有文本索引。元数据覆盖、地学规则命中、文本索引覆盖和字段缺失应分别报告。来源文件的覆盖日期也不等于实时更新。

本计划的目标是确认哪些独立记录属于同一研究的不同版本，并提供发表版优先的浏览；不删除、改写或伪造 OpenAlex W ID。官方 ID 合并／重定向、重复记录、预印本与发表版、更正／撤稿／扩展论文属于不同关系，分别建模。

## 证据和确认策略

| 证据 | 处理方式 |
| --- | --- |
| 已发布 arXiv 记录中已确认的预印本和发表 DOI | 复用现有精确关联证据，将对应 OpenAlex 记录作为首批关系种子 |
| 官方 ID 合并／重定向清单 | 仅在输入实际可用、版本与来源核验后处理；属于标识符解析关系，不等同于学术版本关系 |
| 不同 OpenAlex ID 使用同一 DOI | 先视为重复或冲突候选；核对标题、作者、类型和其他标识符。不能因 DOI 相同就绕过已有歧义保护 |
| 明确的 arXiv ID／源链接或带类型的版本关系 | 解析并保留原始证据，校验目标身份和关系语义后确认 |
| 标题、作者和年份相近 | 仅生成候选，按标注样本校准；不能直接自动归组 |
| 更正、撤稿说明、会议论文的扩展期刊版 | 默认作为独立的有类型关系；无明确证据时不折叠为同一版本组 |

`related_works`、共享作者和引用关系本身都不能证明属于同一研究。短通用标题、重复使用标题、DOI 错填、跨学科同名论文及缺少作者信息应作为负例。不能把 A–B、B–C 的相似关系无条件传递成 A–B–C 的确认组。

## 模块化工作流

1. **固定输入和证据提取。**绑定元数据 generation、arXiv 来源版本、入选地学范围和规则签名。先复用已有 arXiv 关联，再扫描有界的地学种子；候选目标可在全量已导入元数据中解析。保留原始 DOI／ID／链接和 payload 哈希。
2. **候选检索和身份解析。**复用 `Backend.resolve_many/details`、DOI／ID 规范化及现有标题／作者候选检索。按键排序、批量读取、有限并发与持久检查点，避免每个候选重新随机扫描全库。
3. **关系判定。**复用 `arxiv_pipeline.exact_links` 的精确证据原则；为 OpenAlex 内部关系单独保存关系类型、证据、规则版本、已确认／候选／冲突／拒绝及原因，不改变现有来源规则的签名。
4. **独立关系存储和发布。**在独立 ClickHouse 表保存关系边、版本组成员、展示代表及审核记录。发布清单固定输入证明、覆盖范围和统计，保留上一版本和恢复入口。组 ID 是本地 ID，不冒充 W ID；保留跨发布的 ID 映射及拆分／合并历史。
5. **读取视图。**API、网页和导出读取同一份已发布关系版本，返回匹配到的原记录、版本组、证据和优先展示记录。原始 `/works` JSON 和引用表保持不变。

这套关联处理不依赖建立全学科文本索引。精确 ID／DOI 可查询已导入元数据；标题匹配的候选召回仍受已发布文本范围约束。缺少发表版元数据时只能标记待补，不能推断生成记录。

## API、网页和导出分两步交付

**第一步：版本详情与显式选择。**增加独立的版本组读取接口及可选详情视图，展示“命中版本／优先发表版／其他版本”和关联依据。已有 `/v1/works/{id}/versions` 当前返回 arXiv 来源记录；保留它的原有响应语义，不静默将结果改成 OpenAlex 版本列表。新接口及字段在实现时单独声明，本文不表示已经提供。此步骤通常无需重建作品文本索引。

**第二步：可选归组搜索。**原始记录检索保留为默认模式。新增模式需先确定：任一版本匹配即可命中组；文本与年份／OA 等组合条件须在同一成员记录上成立；代表展示版可能与命中版本不同，必须明确标注。组排序基于命中成员，并给出稳定的次级排序。

归组计数、分页和导出都必须基于完整匹配集合，分别报告记录数与组数，不能仅把一页的 20 条结果临时折叠。游标固定查询、索引 build 和关系发布版本。导出区分“全部源记录”和“每组一个展示代表”，并保留成员与证据。若实现需要新的分组属性或辅助索引，单独基准测试并重建受影响部分；不能承诺完整归组搜索永远无需新增索引。

## 字段与引用语义

- 默认展示已确认发表版，并保留切换到预印本或其他成员的入口；撤稿、更正及版本差异必须显式可见。
- 摘要、作者、OA、许可、日期、PDF 链接和 DOI 分别保留版本／来源，不能把一版的 OA 状态或许可复制给另一版。
- 参考文献默认属于当前选中记录；可另提供带出处的“关联发表版书目”。可选跨版本汇总保留原始条目、目标 ID 和未解析项。
- 被引文献按实际引用记录去重展示；不能简单累加各版本 `cited_by_count`。原始计数和派生组计数分别说明。
- 元数据更丰富不等于获得原文参考列表；Crossref 可先小样本评估，全文解析保持后置，普通查询不依赖外网。

## 试跑与验收

先做分层的 1 万至 10 万条地学候选试跑：覆盖已确认 arXiv 种子、缺 DOI／标题变化、同名不同论文、重复 DOI、更正和撤稿等情况。采用人工核验的正负样本，报告自动确认的精确率、置信区间、候选召回评估和待审核比例；不把自生成候选当作完整真值。

检查证据可追溯、冲突拦截、单成员和多成员、不可传递冲突、断点／重放、受控组拆分、发布回退、原 DOI／ID 查询兼容。API／网页／导出必须一致；归组搜索需另外验证完整计数、跨页不重不漏、版本筛选语义和后台负载下的响应时间。

先测每秒候选／详情读取、每条关系存储大小和查询延迟，再估算地学扩容。首批不启动全部 OpenAlex 文献的无界模糊两两比较，也不重建现有地学索引。历史存储校验错误不能作为普通瞬时网络故障无限重试；输入错误或校验失败应停止并保留证据。

## 与后续路线的关系

M2 后续出版商／资助方／项目目录继续独立推进。版本整合先交付高置信关系与详情，再决定归组搜索。M3 的来源更新、删除、重定向和关系增量发布应在 M4 大范围作品扩容之前落实。跨学科新范围按实际需求和小样本成本选择；M5 下载及外部书目恢复保持独立。

## 全索引扩展候选版

v0.6 新增独立的[全索引匹配流程](VERSION-MATCHING.zh-CN.md)：可恢复的精简特征、百万篇试点、独立校准、累积分层批次和候选详情。当前落实关联与详情；分组检索仍为可选后续功能。全量数据处理与真实人工审核分别验收。
